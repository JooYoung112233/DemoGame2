# UI 화면 누락 재감사

2026-08-13 기준 `DESIGN.md`, `UI/SCREEN_ROADMAP.md`, 각 UI 폴더의 README와 실제 미리보기 이미지를 다시 대조했다.

## 결론

주요 게임 루프의 대표 화면은 모두 1차안이 있다. 남은 작업은 새 대형 화면을 무작정 늘리는 것이 아니라, 이미 만든 허브 화면에서 실제로 이동해야 하는 목적 화면과 여러 곳에서 공용으로 쓰는 오버레이·상태 UI를 채우는 것이다.

## 새 이미지가 필요한 항목

### S10. 설정과 확인창

- 설정: `AUDIO`, `VIDEO`, `CONTROLS`, `ACCESSIBILITY` 탭을 한 패널에서 교체한다.
- 공용 확인창: 공연 포기, 타이틀 복귀, 초기화, 종료에 재사용한다.
- 저장 버전 불일치는 같은 확인창의 단일 버튼 변형으로 처리한다.
- 다음 제작 우선순위: `AUDIO` 탭 대표 화면 1장 → 공용 확인창 1장.

### S11. 극장 기록 하위 화면

- 대본 서고 `SCRIPT LIBRARY`
- 유물 창고 `RELIC STORAGE`
- 공연 이력 `PERFORMANCE HISTORY`
- 도감은 이미 제작되어 있으므로 제외한다.

### S12. 공용 선택·상세 오버레이

- 공용 선택창: 대본, 릴, 유물, 캐릭터 목록을 같은 셸에 교체하여 사용한다.
- 공용 상세창: 공연 기록, 재연 기록, 퀘스트 상세에 재사용한다.
- 상점 서비스, 각색 대상 선택, 이벤트 대상 선택, 공연 준비 변경은 별도 전체 화면을 만들지 않고 이 공용 선택창을 연다.

### S13. 전투 상태 컴포넌트 시트

- 적 의도
- 관객 요구와 환호 임계치
- 활성 무대 진행도와 무대 교체
- 침입자 1턴 전 경고
- 커튼콜
- 유품 사용 확인
- 튜토리얼 한 줄 안내

위 항목은 각각 전체 화면을 만들지 않고 기존 전투 화면 위에 얹는 컴포넌트·오버레이 모음으로 제작한다.

### S14. 공용 상태 변형

- 잠김, 비활성, 재화 부족, 코스트 부족
- 빈 목록, 신규 발견 `NEW`, 해금 알림
- 키보드·게임패드 포커스
- 닫힌 커튼 로딩 커버

별도 콘셉트 화면 대신 최종 컴포넌트 정리 단계에서 variant로 만든다.

## 별도 화면을 만들지 않는 항목

- 보스 페이즈 시계, 봉인된 대본, 무료·유료 리롤, 슬롯 3~4칸 변화는 전투 HUD 상태다.
- 일반·엘리트·보스 보상은 기존 보상 모달의 내용 교체로 처리한다.
- 층별 튜토리얼은 독립 튜토리얼 화면 없이 한 줄 안내를 사용한다.
- 맵 이동과 로딩은 기존 맵 화면과 닫힌 커튼 전환을 사용한다.

## Figma 조립 기준

- `00 FLOW MAP`: 축소 화면과 이동 화살표
- `01 FULL SCREENS`: 확정된 1920×1080 화면
- `02 COMPONENTS`: 공용 오버레이와 상태 variant
- `03 PROTOTYPE`: 이미지 위 투명 핫스폿으로 `Navigate to`, `Open overlay`, `Back` 연결

이 문서는 이후 새 화면이 생길 때 중복 제작 여부를 판단하는 기준으로 사용한다.
