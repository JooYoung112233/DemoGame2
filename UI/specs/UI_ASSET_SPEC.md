# 전투 UI 에셋 규격

## 기준 화면

- 기준 해상도: **1920×1080 (16:9)**
- 전투 UI는 해상도 독립 스케일을 사용하되 아래 수치는 1920×1080의 논리 픽셀 기준이다.
- 현재 전체 UI 레퍼런스: `UI/combat/references/modern-combat-ui-variable-slots-cost-v8.png`

## 손패 대본

| 항목 | 1920×1080 표시 크기 | 제작 소스 크기 |
|---|---:|---:|
| 기본 대본 1장 | **172×286 px** | **384×약 533 px** |
| 선택/호버 대본 | **189×315 px** (110%) | 동일 소스 사용 |
| 손패 전체 안전 영역 | **1056×330 px** | 화면 하단 중앙 |

- 기본 손패는 최대 7장을 기준으로 한다.
- 7장일 때 중심 간격은 **약 147px**, 인접 대본 겹침은 **약 25px**이다.
- 손패가 6장 이하면 중심 간격을 늘리되 최대 **172px**를 넘지 않는다.
- 호버한 대본은 Y축으로 **54px** 올리고 110% 확대한다.
- 카드 그림과 수치가 아닌 **대본 베이스 외곽 형상**은 1·2·3코스트 모두 같은 피벗과 바운드를 사용한다.
- 피벗: 하단 중앙 `(0.5, 0.04)`.
- 텍스트·아이콘·코스트·효과 수치는 별도 런타임 레이어로 합성한다.

## 코스트별 두께 판독

| 코스트 | 재질 표현 | 작은 화면에서 남겨야 할 실루엣 |
|---|---|---|
| 1 | 낱장/얇은 캐스팅 시트 | 말린 모서리 1개, 얇은 종이 단면 |
| 2 | 10~14쪽 얇은 제본 대본 | 우측·하단의 좁은 페이지 블록 |
| 3 | 40~60쪽 완성 공연 대본 | 붉은 천등, 굵은 하단 페이지 블록, 보강 모서리 |

## 해상도 운용

- `384px` 폭 소스는 1920×1080에서 약 45%로 표시한다. 작은 글자와 게임 수치는 이미지에 굽지 않는다.
- 2560×1440까지 같은 파일을 사용할 수 있다. 4K 네이티브 대응 시에만 원본에서 `768px` 폭 변형을 별도로 내보낸다.
- 리사이즈 필터는 Lanczos 또는 Bicubic Sharper를 권장한다.

## 런타임 콘텐츠 레이어

대본 베이스 위 콘텐츠는 다음 순서로 분리 합성한다.

1. 코스트 숫자
2. 대본 제목
3. 요구 심볼 3칸
4. 중앙 연출 삽화
5. 핵심 효과 아이콘과 수치

- 기본 손패에서는 코스트 보석, 제목, 요구 심볼, 핵심 효과 아이콘과 수치만 표시한다.
- 효과 설명, 대상, 계열, 강화 문구는 대본 클릭 후 정보 UI에서 표시한다.
- 베이스 텍스처에는 게임 데이터를 굽지 않고 모든 콘텐츠를 교체 가능한 별도 레이어로 둔다.
- 합성 예제: `UI/scripts/examples/cast-cost2-red-sword-monologue-icons-v2-384.png`

### 분리 에셋 권장 크기

| 에셋 | 런타임 파일 | 기본 표시 크기 |
|---|---|---:|
| 피해 아이콘 | `UI/icons/combat/runtime/damage-sword-impact-128.png` | 36~44px |
| 환호 아이콘 | `UI/icons/combat/runtime/cheer-applause-128.png` | 36~44px |
| 코스트 보석 | `UI/icons/resources/runtime/cost-theatre-gem-192.png` | 58~72px |

코스트 보석 중앙 숫자는 이미지가 아닌 폰트 레이어로 표시한다. 한 자리와 `10` 모두 들어오도록 숫자 안전 영역을 보석 안쪽 지름의 55%로 제한한다.

## 슬롯 소품

- 1920×1080 기준 권장 표시 크기: **620×180px**
- 하우징은 항상 4칸이며 시작 슬롯 3칸일 때 네 번째 칸만 커튼 셔터로 닫는다.
- 슬롯 최대치가 4로 증가하면 셔터가 좌우로 열리고 네 번째 릴을 노출한다.
- 각 릴은 상하 롤러 사이를 도는 세로 무한 벨트로 구현한다.
- 화면에는 릴당 심볼 하나만 보이며 위·아래 미리보기와 중앙 페이라인은 표시하지 않는다.
- 자동 스핀 순서: 가속 → 정속 → 개별 감속 → 인덱스 잠금 → 하단 풋라이트 점등.
- 릴별 정지 간격은 0.10~0.16초를 권장한다. 마지막 릴에서 결과 연출을 시작한다.
- 레버는 사용하지 않으며 양쪽 모터 하우징은 자동 회전의 시각적 근거로만 쓴다.

### 런타임 분리 구조

슬롯은 하나의 완성 이미지로 굽지 않고 아래 순서로 합성한다.

1. 각 창에서 Y축으로 반복하는 `UI/slots/slot-reel-repeat-strip.png`
2. 릴에 반복 배치한 개별 심볼
3. 비활성 상태 오버레이(시작 시 네 번째 창 커튼)
4. 최상단 투명 하우징 `UI/slots/slot-machine-housing.png`

- 하우징은 항상 4칸이며 네 창 내부는 완전 투명하다. 가운데 당첨선은 표시하지 않는다.
- 개별 심볼은 `UI/slots/symbols/` 아래 256×256 투명 PNG를 사용한다.
- 심볼은 CAST 8종, MUSIC 9종, PROP 9종과 공용 WILD 1종으로 총 27종이다.
- 한 릴은 같은 심볼 오브젝트를 세로 간격으로 반복 배치하고 Y 좌표만 순환시킨다. 정지할 때 목표 심볼을 창 중앙에 스냅한다.
- 정지 상태에서는 중앙 결과 심볼 하나만 보인다. 위·아래 심볼은 창 밖에 두고 회전 중에만 마스크 영역을 통과시킨다.
- 슬롯 수는 최소 3, 최대 4다. 3칸일 때는 네 번째 릴의 갱신을 멈추고 별도 커튼 오버레이를 표시한다.

## HP·코스트 런타임 레이어

### HP

- 고정 프레임: `UI/hud/hp/frame.png`
- 하트: `UI/hud/hp/heart.png`
- 충전 텍스처: `UI/hud/hp/fill.png`
- 충전 폭은 `현재 HP / 최대 HP` 비율로 가로 마스킹한다.
- `현재 / 최대` 숫자는 이미지에 굽지 않고 우측 안전 영역에 런타임 폰트로 표시한다.

### 코스트

- 고정 프레임: `UI/hud/cost/frame.png`
- 가면 문장: `UI/hud/cost/mask.png`
- 소켓 상태: `socket-lit.png`, `socket-empty.png`, `socket-locked.png`
- 소켓은 항상 절대 최대치인 10개를 배치한다.
- 인덱스가 현재값보다 작으면 점등, 현재값 이상이면서 현재 최대치보다 작으면 빈 소켓, 현재 최대치 이상이면 잠금 소켓을 사용한다.
- 코스트 범위는 최소 3, 절대 최대 10이며 `현재 / 현재 최대` 숫자는 런타임 폰트로 표시한다.
