## 이 프로젝트가 뭔지 한 줄로

3릴 슬롯을 돌려 전투하고, 상점에서 **릴 내부 심볼 구성 자체를 사고팔며** 성장하는 오페라 극장·서커스 테마 로그라이트. PC 세로 화면. Unity 6000.2.1f1.

**설계 중심축:** 릴 = 눈에 보이는 덱. 스핀 = 드로우. 상점 = 덱빌딩.

## 절대 흔들지 말 것

이 결정들은 여러 차례 검토를 거쳐 확정됐다. 바꾸려면 근거가 있어야 한다.

- **기본 처리는 항상 무료로 존재한다.** 기술 0개로도 게임이 굴러가야 한다. 그래서 기술을 봉인·처벌하는 보스가 성립한다
- **자원은 🎟 회전권 하나.** 앙코르·기술 승급·넛지가 모두 이 하나를 두고 경쟁한다
- **매 턴 반드시 뭔가 일어난다.** 헛턴 없음. 1줄은 무조건 돌아간다
- **랜덤은 계획 가능해야 한다.** 적 릴은 한 턴 미리 공개하고, 미리보기 칸을 보여주고, 교정 수단(넛지)을 판다
- **UI는 명도로 분리하고 채도로 분리하지 않는다.** 채도를 올리면 즉시 모바일 카지노 앱처럼 보인다
- **idle은 코드 애니메이션, 공격은 프레임 시트.** 이유는 DESIGN.md 15.1

브라우저에서 파일을 직접 열면 된다. 빌드 과정 없음.

- **[wireframe/combat.html](../../../wireframe/combat.html)** — 전투 화면 그레이박스. 열면 밴드·요소 크기가 실시간 실측으로 표시되고 기준 위반이 판정된다. 레이아웃을 바꿀 땐 여기서 먼저 숫자를 확인한다
- **[tools/spritesheet.html](../../../tools/spritesheet.html)** — 스프라이트 시트 검사·정렬·내보내기. 시트를 붙여넣으면 캐릭터를 자동 감지해 자르고, 정렬 편차와 프레임 변화율을 판정하고, 균등 셀 PNG·낱장·GIF로 내보낸다. 설정은 자동 저장된다
- **enemy_animation/** — 적 애니메이션 원본과 작업 규칙 (사용자가 관리)

## 작업 방식

이 사용자와 일할 때의 규칙이다.

- **설계를 먼저 대화로 다듬는다.** "만들자"는 말이 나와도 곧바로 파일을 쓰지 말고, 트레이드오프와 추천안을 제시하고 합의를 받는다. 단순 나열이 아니라 **함정을 지적하고 대안과 이유를 함께** 주는 것을 선호한다
- **합의된 규칙은 즉시 문서로 고정한다.** 대화로 들고 있지 않는다
- **레이아웃·수치는 눈이 아니라 측정으로 검증한다.** 그레이박스를 실제 해상도로 열어 숫자를 읽는다. 실측이 SPIN 버튼 폭 버그처럼 눈으로 못 잡는 문제를 잡아냈다
- **커밋 메시지는 한국어가 아니라 영어 산문으로**, 무엇을·왜 바꿨는지 쓴다. 큰따옴표를 넣으면 PowerShell here-string 파싱이 깨지니 피하거나 `git commit -F` 를 쓴다
- **`git add -A` 를 쓰지 않는다.** 파일을 명시한다. 한 번 원치 않는 이미지가 히스토리에 들어갔다
- 커밋은 사용자가 요청할 때 한다

## 아트 요청 시 주의

- 스프라이트 배경은 **마젠타 `#FF00FF`** 로 요청한다. 어두운 자주 배경은 광대 옷 그림자와 색이 가까워 투명화할 때 외곽이 깎인다
- **idle 시트를 요구하지 않는다.** 프레임마다 새로 그려져서 반복 재생 시 픽셀이 끓는다. idle은 정지 스프라이트 한 장만 받는다
- 공격 시트는 **골반 피벗 고정**, **이펙트 미포함**을 명시한다
- 레퍼런스는 **배경 판과 UI 판을 따로** 뽑는다. 한 장에 다 담으려 하면 분위기와 게임성 중 하나가 죽는다
