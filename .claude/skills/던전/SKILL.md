## 이 프로젝트가 뭔지 한 줄로

3릴 슬롯을 돌려 나온 심볼로 **대본을 지어 상연하고**, 상점에서 **릴 내부 구성 자체를 사고팔며** 성장하는 다크 판타지 인형극 로그라이크 덱빌더. PC 세로 화면.

**정식 제목** — `UNSCRIPTED · UNDERSTUDY · UNCAST` / 한글 「대역」. 대본이 없어서(1막) 대역을 서고(2막) 그래서 놓여난다(3막). 다만 60.10 에서 **최종 확정은 보류** 상태다.

**설계 중심축:** 릴 = 눈에 보이는 덱. 스핀 = 드로우. 상점 = 덱빌딩. **무대 = 빌드의 정체성**(51장).

**핵심 판타지:** *"나는 싸우는 게 아니라 죽음을 연출한다."*

**한 판의 모양** — 3막 × 12층 = 36층. 막마다 보스. 슬롯 3칸(복원으로 4칸). 대본 보유 7장. 코스트로 상연한다.

> **서커스 테마는 폐기했다**(23장). 이미 만든 아트는 그대로 쓴다 — 광대는 역할 심볼, 나무 인형은 인형극 그 자체, 곰은 배역에 갇힌 배우다.

## 절대 흔들지 말 것

이 결정들은 여러 차례 측정을 거쳐 확정됐다. 바꾸려면 근거가 있어야 한다.

- **기본 처리는 항상 무료로 존재한다.** 대본 0장으로도 게임이 굴러가야 한다. 그래서 대본을 봉인·처벌하는 보스가 성립한다
- **전투 중 자원은 코스트 하나.** 이월 없음, 턴당 3~5. 자원이 **하한을 막으면**(옛 「큐」) 답답하고 **상한을 정하면** 고르는 즐거움이다 — 방향이 반대라는 것이 7.3 의 결론
- **매 턴 반드시 뭔가 일어난다.** 헛턴 없음. 페이라인 한 줄은 무조건 돌아간다
- **랜덤은 계획 가능해야 한다.** 적의 **다음 대사를 내용까지 미리 공개**하고(48장), 미리보기 칸을 보여주고, 교정 수단(넛지)을 판다
- **어려운 조합일수록 강해야 한다**(49장). 3종이 1종보다 21배 어려운데 코스트당 값이 같았던 적이 있다. 일반 덱을 깎지 말고 **어려운 쪽을 올려서** 맞춘다
- **무대는 선포하지 않는다**(51.3). "이번 판은 거울 무대!"를 선언하게 하면 덱 짜기가 체크리스트 채우기가 된다. 진행도가 발동선을 넘으면 상점·보상이 **조용히** 기운다. 기울기 없이 480판 돌렸더니 무대가 열린 횟수 **0회**였다
- **일반 무대 6종은 본편에 남긴다**(69.1). 빌드 재미까지 전부 재연에 두면 클리어율 16~20% 인 이 게임에서 대부분이 절반을 못 본다
- **퍽은 그 단계가 올린 난이도보다 작아야 한다**(69.3). 다 갚아주면 재연이 등반이 아니라 제자리가 된다
- **난이도는 HP를 먼저 올리고 공격을 마지막에 쓴다.** 공격 4배를 올려도 턴 수가 3.00 → 2.99 다. 판단 횟수는 안 늘고 사망률만 오른다
- **UI는 명도로 분리하고 채도로 분리하지 않는다.** 채도를 올리면 즉시 모바일 카지노 앱처럼 보인다
- **idle은 코드 애니메이션, 공격은 프레임 시트.** 이유는 DESIGN.md 21.1

## 작업 방식

이 사용자와 일할 때의 규칙이다.

- **설계를 먼저 대화로 다듬는다.** "만들자"는 말이 나와도 곧바로 파일을 쓰지 말고, 트레이드오프와 추천안을 제시하고 합의를 받는다. 단순 나열이 아니라 **함정을 지적하고 대안과 이유를 함께** 주는 것을 선호한다
- **합의된 규칙은 즉시 문서로 고정한다.** 대화로 들고 있지 않는다
- **밸런스는 의견이 아니라 측정으로 정한다.** agents.html 로 돌려서 숫자를 보고 말한다. "약한 것 같다"가 아니라 "승률 24%, 스프레드 19pp"로 말한다
- **레이아웃·수치는 눈이 아니라 측정으로 검증한다.** 그레이박스를 실제 해상도로 열어 숫자를 읽는다
- **숫자가 안 움직이면 손잡이가 아니라 저울을 먼저 의심한다**(80.5). 이 프로젝트에서 세 번 반복된 실패다 — 커튼콜이 시뮬레이터에서 아예 작동하지 않은 채 밸런스를 쟀고(52.2), `selfDamage` 를 `selfDmg` 로 세서 캐릭터 하나가 통째로 죽어 있었고(56.5), `killedBy` 가 마지막 타격자가 아니라 첫 번째 적을 기록해 근거 없는 하향을 두 번 했다
- **측정 인덱스를 묶지 말 것**(54장). 캐릭터 8종 × 숙련도 4종을 `i%8`·`i%4` 로 배정하면 특정 캐릭터가 항상 최저 숙련도를 받는다. `SK[floor(i / CHARS.length) % SK.length]` 로 돌린다
- **커밋 메시지는 한국어가 아니라 영어 산문으로**, 무엇을·왜 바꿨는지 쓴다. 큰따옴표를 넣으면 PowerShell here-string 파싱이 깨지니 피하거나 `git commit -F` 를 쓴다
- **`git add -A` 를 쓰지 않는다.** 파일을 명시한다. 한 번 원치 않는 이미지가 히스토리에 들어갔다
- 커밋은 사용자가 요청할 때 한다
- **세션 끝에 세션 기록을 남긴다.** 다른 PC에서 이어받는 유일한 통로다 — 아래 참조

## 여러 PC에서 이어서 작업하기

대화 기록은 이 PC의 로컬 세션에만 있다. 기기를 넘어가는 것은 **저장소 파일뿐이다.**

```powershell
# 이어받기
git pull   →   /던전

# 세션이 끝나면 — 기록을 만들고 채운 뒤 커밋·push
.\scripts\new-session-log.ps1 -Title "전투 UI 수정"
.\scripts\publish-session.ps1 -Message "docs: record combat UI session"
```

그래서 결정을 대화에 남기지 않고 문서에 적는다. **확정된 규칙은 `DESIGN.md` 에 장으로, 무엇을 왜 정했는지는 `SESSION_LOGS/sessions/` 에.** 이미지는 `SESSION_LOGS/images/` 에 넣고 상대 경로로 건다.

**대화 원문(jsonl)은 커밋하지 않는다.** 시행착오와 폐기된 안이 섞여 있어 새 세션이 확정된 것과 버린 것을 구분하지 못한다 — 23장이 폐기안을 따로 기록하는 이유와 같다.

## 아트 요청 시 주의

- 스프라이트 배경은 **마젠타 `#FF00FF`** 로 요청한다. 어두운 자주 배경은 광대 옷 그림자와 색이 가까워 투명화할 때 외곽이 깎인다
- **idle 시트를 요구하지 않는다.** 프레임마다 새로 그려져서 반복 재생 시 픽셀이 끓는다. idle은 정지 스프라이트 한 장만 받는다
- 공격 시트는 **골반 피벗 고정**, **이펙트 미포함**을 명시한다
- 레퍼런스는 **배경 판과 UI 판을 따로** 뽑는다. 한 장에 다 담으려 하면 분위기와 게임성 중 하나가 죽는다
